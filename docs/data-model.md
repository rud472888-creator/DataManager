# Data Model

Working root: `~/desktop/datamanager`.

## Entity Inventory

The local runtime owns writes to all entities. The remote web console reads and submits requests through REST/WebSocket only.

## `jobs`

| Field | Nullable | Notes |
|---|---|---|
| `job_id` | no | Primary key, stable public ID |
| `project_name` | no | Operator-provided project label |
| `source_volume_id` | no | Runtime-managed volume ID |
| `dest_main_id` | no | Runtime-managed destination ID |
| `dest_backup_id` | yes | Runtime-managed destination ID; nullable only if a later policy allows main-only |
| `state` | no | Canonical job state |
| `current_step` | yes | scanning, copying, verifying, parsing, capturing, reporting |
| `created_at` | no | UTC timestamp |
| `started_at` | yes | UTC timestamp |
| `ended_at` | yes | UTC timestamp |
| `stats_json` | no | Counts, bytes, speed, ETA, warnings, errors |
| `policy_json` | no | Retry, checksum, exclude, copy options |
| `operator_origin` | no | local web, remote web, local panel |
| `recovery_cursor_json` | yes | Last safe checkpoint for restart recovery |

Recovery-critical fields: `state`, `current_step`, `stats_json`, `policy_json`, `recovery_cursor_json`, source/destination IDs, and timestamps.

## `job_events`

| Field | Nullable | Notes |
|---|---|---|
| `event_id` | no | Primary key |
| `job_id` | yes | Nullable for runtime-level events |
| `event_type` | no | state_changed, command_requested, command_rejected, warning, error, report_ready |
| `state_before` | yes | Previous state for transitions/commands |
| `state_after` | yes | Result state for transitions/commands |
| `command` | yes | pause, resume, cancel, retry, refresh |
| `accepted` | yes | Command decision |
| `reason` | yes | Human-readable reason |
| `payload_json` | no | Structured event details |
| `created_at` | no | UTC timestamp |
| `operator_origin` | yes | remote web, local panel, runtime |

Events are append-only and feed WebSocket deltas plus log views.

## `clips`

| Field | Nullable | Notes |
|---|---|---|
| `clip_id` | no | Primary key |
| `job_id` | no | Parent job |
| `file_id` | no | Parent file |
| `format_name` | no | Parser-reported format name when metadata parsing is available |
| `parser_version` | no | Adapter version or mock version |
| `metadata_json` | no | Camera, reel, timecode, resolution, fps, duration when available |
| `integrity_status` | no | unknown, ok, warn, failed |
| `capture_status` | no | unavailable, pending, captured, failed |
| `created_at` | no | UTC timestamp |

Real parser uncertainty is represented through capability and status fields, not fake metadata. Multiformat offload/checksum can complete even when metadata parsing is unavailable.

| Field | Nullable | Notes |
|---|---|---|

| `label` | no | Operator-facing label |

## `settings`

| Field | Nullable | Notes |
|---|---|---|
| `key` | no | Primary key |
| `value_json` | no | Structured setting value |
| `updated_at` | no | UTC timestamp |

Settings can include token metadata, allowed destination root policy, UI preferences, and dependency/capability cache.

## Candidate Keys And Relationships

- `jobs.job_id` is referenced by `job_events`, `job_files`, `clips`, and `reports`.
- `job_files.file_id` is referenced by `clips`.
- `system_volumes.volume_id` is referenced by jobs for source/main/backup IDs.
- `reports.artifact_relpath` is unique per job/report type.
- `job_events.event_id` is suitable as a WebSocket cursor.

## Recovery Notes

Recovery should query jobs in `QUEUED`, `PAUSED`, `WARN`, and `FAILED`. Jobs interrupted in active states should be inspected through persisted events and file checkpoints before retrying or surfacing a repair state. Automated recovery must be conservative and must not delete or overwrite media without explicit runtime policy.
