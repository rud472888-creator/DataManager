# Sprint 3 - Parsing, Frame Capture & Reports Contract

Working root: `~/desktop/datamanager`.

## Goal

Convert verified file results into runtime-generated metadata, optional frame captures, and report artifacts while preserving BRAW capability truthfulness.

## Scope

- Runtime metadata parsing after verified offload.
- Clip metadata persistence.
- Runtime frame-capture integration path.
- Report artifact generation:
  - checksum PDF
  - image PDF when frame capture produced frames
  - metadata XLSX
  - manifest.json
- Report artifact persistence.
- Tests with mock parser success and real-adapter unavailable behavior.

## Out Of Scope

- Browser report generation.
- Real BRAW SDK bundling.
- Visual report polish beyond simple operational black/white output.
- API report download routes.
- Full report center UI.

## Lifecycle Timing

Parsing occurs after copy/checksum verification. Capture occurs after successful metadata parse when parser capability allows it. Reporting occurs after parse/capture attempts and records both ready and unavailable artifacts truthfully.

## Required Artifact Outputs

- `00_master/reports/checksum.pdf`: checksum/file-status summary.
- `00_master/reports/image.pdf`: frame summary only when frames exist.
- `00_master/reports/metadata.xlsx`: metadata table artifact.
- `00_master/manifests/manifest.json`: machine-readable job/file/clip/report summary.

## Fallback / Partial Behavior

- Real BRAW metadata unavailable: do not fabricate clip metadata.
- Real BRAW frame capture unavailable: do not create fake image PDF.
- Mock parser may create deterministic metadata/frames only in tests and is marked as mock.
- Missing image PDF due unavailable capture is acceptable in development when the report record says `unavailable`.

## v1 Completion Gates vs Development Gaps

Blocks full production-grade BRAW readiness:

- No real BRAW SDK command configured.
- No real sample media validated.
- No real frame-capture command validated.

Acceptable development state:

- Mock parser tests prove runtime integration and artifact plumbing.
- Real adapter reports unavailable/partial truthfully.
- Checksum, metadata, manifest, and report indexes are generated by runtime code.

## Acceptance Criteria

- Runtime code, not web console, generates artifacts.
- Clip metadata and report records persist.
- Mock parser success and real unavailable paths are both tested.
- Unavailable capture does not produce fake frames or fake image PDF.

## Implementation Notes

Implemented runtime parse/capture/report path:

- `app/runtime/parse.py` parses verified/warn file results through a runtime parser and persists clips.
- `app/runtime/capture.py` integrates parser frame capture and returns unavailable without creating fake frames.
- `app/runtime/reports.py` generates checksum PDF, metadata XLSX, manifest JSON, and an image PDF only when frames are available.
- `app/persistence/models.py` defines `Clip` and `Report`.
- `app/persistence/repositories.py` persists clips and report artifact records.
- `tests/runtime/test_parse_capture_reports.py` covers mock parse success, real parser unavailable behavior, capture unavailable behavior, and report artifact persistence.
